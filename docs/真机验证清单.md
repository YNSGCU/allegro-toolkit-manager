# Allegro 真机验证清单

> 目的：验证 ATM 的「实时交互」能力（配色 / DRC / 会话控制台 / 多环境自动加载）
> 在真实 Allegro 会话上端到端可用。目前这些能力只在 fixture 上测过，尚未在真机跑通。

## 一、前置准备

1. 安装 Allegro 17.2 与 17.4（至少一个版本）。
2. 安装 `allegro-vibe-bridge` 技能（提供 `vibe_server.il`），确认其 `workspace/` 目录存在。
3. 设置环境变量（二选一）：
   - `ATM_VIBE_WORKSPACE=<workspace 绝对路径>`，或
   - 使用默认路径 `~/.codex/skills/allegro-vibe-bridge/workspace`。
4. 在 Allegro 命令窗执行（或让 ATM 自动写入 ilinit 后重启）：
```
skill load("<vibe_server.il 绝对路径>")
```

## 二、验证项

### 1. 桥接连通（所有功能的地基）

- 打开 ATM「配色」页，看桥接状态胶囊是否显示 **已连接**，并正确显示 Allegro 版本与程序名。
- 打开「会话控制台」，看快照的版本/设计/单位是否正确。

### 2. 配色链路

| 步骤 | 操作 | 预期 |
|---|---|---|
| 捕获 | 配色页「从 Allegro 捕获」 | 得到当前板子 24/192 色板 + 背景 + 图层列表 |
| 应用 | 选方案「应用到板子」 | 板子配色变化，返回 applied/skipped 计数 |
| 实时预览 | 编辑调色板 → 「实时预览」 | 板子调色板即时变化，图层分配不变 |
| 撤销 | 「撤销本次配色」 | 恢复应用前的板子配色 |
| 跨版本 | 17.2 捕获 → 17.4 应用 | 192 色板不报错、不截断 |

**重点核对 SKILL 语法**：`axlColorSet('all '(...))`、`axlColorGet('count)` 在不同版本的实际返回值。

### 3. DRC 链路

- DRC 看板「在线抓取」，核对：总数、rule/type/actual/expected/layer/net/xy/waived/fixed 字段是否解析正确。
- 与手动导出 `.rpt` 后「导入报告」的结果对比，确认双通道一致。

**重点核对**：`axlDBGetDesign()->drcs` 遍历输出的格式（%L 引号 / nil / 多值），与 `core/drc/drcBridge.ts` 的解析一致。

### 4. 会话控制台

| 操作 | 预期 |
|---|---|
| 执行 `axlCurrentDesign()` | 返回当前设计名 |
| 执行写命令（如 `axlDBSet`） | 弹出二次确认，确认后执行并记录历史 |
| 命令历史 / 收藏 | 跨会话保留，收藏可一键重跑 |

### 5. 多环境自动加载

- 配色页「自动启用桥接」→ 生成 Apply Plan → 写入所有已发现环境的 `allegro.ilinit`。
- 重启 Allegro 后，桥接应自动加载（无需手动 `skill load`）。

### 6. 真实样本校准（不需要运行 Allegro，导出文件即可）

请提供以下真实文件，用于回归校准解析器（当前全用模拟 fixture）：

- DRC 报告：17.2 / 17.4 各一份 `.rpt` + 一份 Extracta CSV
- 配色：一份 `.col` 文件
- 环境：真实 `env`、`allegro.ilinit`、`.men` 文件

### 7. 发布与升级链路（NSIS / electron-updater）

前置：GitHub 仓库 + `GH_TOKEN`（repo 写权限）；`npm run publish:github` 会串行执行
完整构建（`npm run build`）→ electron-builder 打包 → `gh` 上传
`ATM-Setup-x.x.x-x64.exe` + `latest.yml` + `blockmap` 到 Release。
发布前门禁：`npm run verify`（security + lint + format + typecheck + test + build）与
`npm run verify:update`。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 全新安装 | 双击 NSIS 安装包 | 可选安装目录、桌面/开始菜单快捷方式、首次启动正常生成默认工作区 |
| 更新源配置 | 查看设置页 / 更新日志 | 版本号显示正确；`atmUpdateFeedUrl` 已写入安装包（generic provider） |
| 增量升级 | 发布 vN+1 后启动 vN | 自动/手动检测到新版本，下载 latest.yml + blockmap + exe，安装过程不损坏 |
| 升级后数据 | 升级完成后重新打开 | `workspaces.json`、`applied_profile.json`、各方案、配色/DRC/会话历史原样保留 |
| 回滚 | 手动安装旧版安装包 | 旧数据兼容读取，Apply Plan 的 SHA256 备份与回滚清单仍可用 |
| 失败场景 | 断网检测 / 下载损坏文件 | 明确中文错误提示；失败不覆盖现有配置 |
| 多实例 | 升级时旧实例未退出 | 有明确提示或自动结束旧实例，安装不悬挂 |

### 8. 跨版本方案同步（V6.4）

前置：两套环境（17.2/17.4）在 ATM 环境页各有独立 pcbenv 目录；先在各方案页
从当前环境「构建并保存」快捷键 / Skill / 菜单方案（空方案会导致同步直接提示）。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 生成清单 | 工作区页 → 跨版本同步 → 选择源/目标 → 生成差异清单 | 通用命令归入“同步”，高版本特有命令归入“版本特有”并列出提供者原因 |
| 覆盖决策 | 修改某条决策为强制同步/跳过 | 再次生成保持不变（决策随 apply 生效） |
| 执行同步 | 确认同步到目标环境 | 目标环境新增「（同步）」方案，现有方案未被修改 |
| 应用 | 在目标环境绑定新方案并按 Skill→菜单→快捷键应用 | 写入走 Apply Plan，冲突/备份正常；17.2 打开后无高版本命令报错 |
| 规则记忆 | 同步后查看 `sync_rules.json` | 用户强制的命令对已记忆，下次默认沿用 |
| 反向 | 17.2 → 17.4 反向同步 | 流程对称，通常 B 类极少 |

2. `vibe_in.il` 与 `vibe_out.log` 的内容（桥接相关问题时）

4. 复现步骤

## 四、已知风险点（开发时标注，真机需重点验证）

1. **DRC 报告无统一格式**——双通道兜底，需真实样本校准。
2. **SKILL 语法跨版本差异**——192 色板、`drcs` 字段、`%L` 输出的引号/nil 处理。
3. **编码**——GBK（17.2）与 UTF-8（17.4+）的写入/读取。
4. **桥接共享文件并发**——已做串行化，真机需验证多操作连续触发不串扰。
