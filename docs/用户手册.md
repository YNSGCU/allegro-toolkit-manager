# ATM - 用户手册

## 简介

ATM（Allegro Toolkit Manager）是一个个人 Allegro 工作环境配置管理工具。

**它能做什么：**
- 🔍 **看懂** 自己的 Allegro 本地配置环境（HOME / pcbenv / env 在哪里）
- ⌨️ **安全修改** 快捷键（funckey / alias），自动备份可回滚
- 📦 **管理** 个人 Skill 脚本
- 📋 **可视化编辑** Allegro 菜单（ATM 托管 Overlay）
- 💾 **备份与恢复** 配置和个人工作习惯

**当前版界面：** 简化工作台 UI
- 侧栏使用 **快捷键 / Skill / 菜单 / 系统状态** 四个入口，环境详情并入系统状态
- 方案栏只常驻 **方案选择 + 方案管理 + 必要的审阅动作**
- 正常状态合并显示，优先提示错误、警告和待应用更改
- 快捷键拆分为 **键位 / 列表 / 冲突** 三个任务页签
- 菜单以菜单树为唯一主工作区，命令清单和引用检查收进工作区工具

**它不做什么：**
- ❌ 不修改 Allegro 主程序目录
- ❌ 不修改公司云端 Skill 仓库
- ❌ 不修改公司菜单模板
- ❌ 不修改 license 配置

## 快速开始

### 安装

普通用户可直接运行发布产物 `ATM-Setup-<版本>-x64.exe`，按向导选择安装目录。当前内部构建未配置代码签名，Windows 可能显示 SmartScreen 提示；正式对外发布前应完成签名。

需要参与开发时再使用源码方式：

```powershell
# 1. 克隆/下载项目到本地
# 2. 进入项目目录
cd D:\AllegroDevOpsTool

# 3. 安装依赖（使用国内镜像，避免 Electron 下载失败）
npm install --registry=https://registry.npmmirror.com
```

### 启动应用

已安装版本从开始菜单或桌面快捷方式启动。以下双终端方式仅用于源码开发：

需要打开两个终端窗口：

**终端 1：启动前端服务器（保持窗口开着）**
```powershell
cd D:\AllegroDevOpsTool
npx.cmd vite
```
看到类似 `VITE v6.4.3 ready in 362 ms → http://localhost:5173/` 就说明就绪了。

**终端 2：启动桌面应用**
```powershell
cd D:\AllegroDevOpsTool
npx.cmd tsc -p tsconfig.electron.json
$env:VITE_DEV_SERVER_URL="http://localhost:5173/"
npx.cmd electron dist-electron/electron/main.js
```

### 关闭应用

直接关掉 Electron 窗口即可。Vite 终端按 `Ctrl+C` 停止。

## 页面说明

### 系统状态

首页显示当前环境的整体状态：

```
环境健康评分: 85/100（安全）
pcbenv:    ✅ D:\Cadence\SPB_Data\pcbenv（可写）
env:       ✅ 存在（可读可写）
ilinit:    ⚠️ 不存在（首次使用）
```

- 点击 **快捷键** 卡片可跳转到快捷键管理
- 点击 **重新扫描** 刷新环境信息
- 有 3 个文件状态卡片展示核心文件

### 环境详情

详细的环境诊断页面：

**自动检测路径：**
显示四个优先级的检测结果，从 HOME 环境变量到常见 Cadence 路径。

**文件状态卡片：**
- HOME 目录
- pcbenv 目录（可写/只读）
- env 文件（存在/可读/可写）
- allegro.ilinit（存在/可读/可写）
- atm_generated 托管目录

**操作：**
- 📁 **手动选择 pcbenv 目录** — 如果自动检测没找到，点击手动选择
- 🔄 **自动检测** — 重新扫描环境变量

左侧栏底部可选择 Allegro 管理目标。“切换环境”只改变 ATM 读写的 `pcbenv`；“按此环境启动”会为新 Allegro 进程设置匹配的 `HOME/CDSROOT`。若侧栏提示系统 HOME 与管理目标不一致，请关闭旧 Allegro 窗口并使用该按钮，不要直接从桌面快捷方式启动。

**环境变量表：**
显示 HOME / USERPROFILE / HOMEDRIVE / HOMEPATH / CDS_SITE / SKILL_PATH 的当前值。

### ⌨️ 快捷键管理

查看和管理 env 文件中的快捷键。页面采用**三层结构**，从上到下依次展示：

#### 方案栏（V5.6）

页面顶部统一方案栏：

```
当前方案：[自用 ▼]                 [方案管理 ▼] [审阅更改]
已同步时：当前方案：[自用 ▼]       [方案管理 ▼]  已应用
```

**方案切换（预览模式）：**
- 下拉切换方案时**只预览方案内容**，不直接写 env
- 切换后出现 **审阅更改** 操作
- 已应用状态显示为绿色文字，不占用按钮位置

**应用此方案流程：**
1. 点击 **审阅更改**
2. 系统生成 Apply Plan（预览 → 备份 → 写入 → 记录历史）
3. 用户确认执行后写入 env
4. 状态更新为 ✅ 已应用

**安全删除方案：**
- **删除方案** 使用应用内确认弹窗
- **默认方案**不可删除
- **当前正在使用的方案**不可直接删除，需先切换

**其他操作：**
- 新建、复制、重命名、删除、导入和导出都在 **方案管理** 中

#### 全局状态总览（V5.6）

方案栏下方显示紧凑状态摘要，优先展示异常和待处理项：

```
配置：38 条 · 未发现问题      env：已连接
```

状态颜色：
- 🟢 **绿色** = 正常 / 已完成
- 🟡 **黄色** = 警告 / 需要操作
- 🔴 **红色** = 错误
- ⚪ **灰色** = 未涉及

#### 三个任务视图

- **键位**：专门查看键盘占用，点击键位可直接编辑、接管或新增绑定
- **列表**：集中搜索、筛选全部快捷键，选中后在右侧查看详情和执行编辑
- **冲突**：只展示需要处理的覆盖、重复和引用风险
- 导入 env、方案导入导出、速查表和变更历史位于 **工作区工具 → 导入、导出与历史**

#### Env 来源与导入导出

从 **工作区工具 → 导入、导出与历史** 查看多 env 来源：

```
当前编辑 env：D:/.../pcbenv/env    可写
共 3 个 env 来源（2 个参考）  最终层级：用户 env > 参考 env > 默认/保留库  [📂 管理 env 来源]
```

- **当前编辑 env**：ATM 当前使用的用户 env 路径，只有这个 env 可以被 Apply Plan 修改
- **参考 env**：其他自动检测到的 env（安装默认、站点、公司配置），只读参考，不可直接编辑
- **管理 env 来源按钮**：打开 Env 来源管理弹窗

**Env 来源管理弹窗：**
- 显示所有检测到的 env 文件，按类型分组：用户 env / 参考 env / 自动检测 env
- 每个条目显示：路径、角色、可读写、快捷键数量、最后修改时间
- 操作：设为活动 env、添加参考 env（文件选择对话框）、移除参考 env
- 可写用户 env 可设为当前编辑对象，只读 env 不可直接编辑

#### Layer 1：键盘占用总览

一个物理键盘布局图，顶部有**工具行**和**层级工具栏**，彩色按键直观显示 funckey 的占用情况。

**顶部工具行（两个切换区）：**

```
┌────────────────────────────────────────────────────┐
│ ⌨️ 键盘占用总览    [⌨️ 我的] [🔒 默认] [📌 全部]   │  ← 全局视图切换
├────────────────────────────────────────────────────┤
│ 当前层: 普通层   [普通] [大写] [Ctrl] [Alt] [特殊] │  ← 层级工具栏
├────────────────────────────────────────────────────┤
│  [键盘 — 等比例缩放，小窗口可横向滚动]               │
└────────────────────────────────────────────────────┘
```

**全局视图模式（左侧工具行）：**

| 视图 | 按键颜色 | 说明 |
|------|---------|------|
| ⌨️ **我的快捷键** | 🟢 绿色占用 | 只显示用户自己绑定的快捷键 |
| 🔒 **默认/保留键** | 🔵 蓝色只读 | 显示 Allegro 默认占用和系统保留键 |
| 📌 **全部叠加** | 🟡 黄色警告 | 同时显示两者，冲突键显示覆盖风险 |

切换全局视图模式会影响：统计卡片、键盘占用总览、快捷键地图、详细表格、冲突检测。

> **⚠️ 数据来源说明：** 默认/保留键数据来自 `public/data/default_reserved_keys.json` 快捷键参考库，
> 通过前端 `fetch('/data/default_reserved_keys.json')` 直接加载，**不是**从 env 文件解析出来的。
> env 文件只包含用户自定义快捷键。如果参考库文件不存在或加载失败，页面顶部会显示黄色警告提示。

**图层按钮（V3.0 图层工具栏 + 切换行为）：**

| 按钮 | 点击第一次 | 再点击一次 |
|------|-----------|-----------|
| **普通** | 回到普通层（无论当前在哪层） |
| **大写** | 进入大写层 | 回到普通层 |
| **Ctrl** | 进入 Ctrl 层 | 回到普通层 |
| **Alt** | 进入 Alt 层 | 回到普通层 |
| **特殊** | 进入特殊层 | 回到普通层 |

**过滤规则：**

| 图层 | 显示内容 |
|------|---------|
| **普通层** | 无修饰键 + 非大写字母（小写字母 `s` + F1/数字等） |
| **大写层** | 无修饰键 + 大写单字母（`S`、`F`、`C`） |
| **Ctrl 层** | modifiers 包含 Ctrl（`Ctrl+S`、`~s`） |
| **Alt 层** | modifiers 包含 Alt（`Alt+F4`） |
| **特殊层** | modifiers 包含 Shift 或 layer 为 special（`Shift+wheel_up`） |

你也可以直接点击键盘上的 **Ctrl**/**Alt**/**Shift** 键帽来切换对应图层（相同的 toggle 行为）。

**键盘颜色：**
- 🟢 **绿色** = 有绑定（当前层占用）
- 🔴 **红色** = 有冲突（重复绑定）
- 🟡 **黄色** = 覆盖风险（叠加视图中用户覆盖了默认键）
- ⚪ **灰色** = 未占用
- 🔵 **蓝色选中** = 修饰键激活状态
- 按键右上角显示绑定数量圆点（修饰键不显示）

**点击按键：** 打开物理键绑定管理面板，显示该物理键的所有 funckey 绑定详情（含 displayKey、图层标签、中文名、**快捷键来源**标签、**命令来源**标签、状态、行号），并支持编辑/删除/接管/修正来源/新增绑定操作。

**键盘响应式：**
- 宽屏下键盘保持正常大小居中显示
- 窗口缩小时键盘等比例缩小（最小 0.82×）
- 窗口过小出现横向滚动条，键盘排布不变

**点击按键 — 物理键绑定管理面板（V2.2）：**

点击键盘上的物理键（如 `S`、`F1`、`Esc`）后，键盘下方会展开一个管理面板，显示该物理键的所有 funckey 绑定。

面板顶部的筛选切换控制显示范围：
- **全部绑定**：显示该物理键下的所有绑定（小写、大写、Ctrl 组合等）
- **仅当前层**：只显示当前图层匹配的绑定

每个绑定显示为一张卡片，包含：
- 绑定键名 + 图层标签（小写/大写/Ctrl 层/Alt 层/特殊层）
- 中文命令 + 原始命令
- 快捷键来源标签 + 命令来源标签
- 状态 + 行号

操作按钮：
- **✏️ 编辑**：打开编辑对话框，修改后生成 Apply Plan
- **🗑️ 删除**：确认后生成注释删除的 Apply Plan
- **📋 接管**：将原始 env 的绑定安全接管到当前方案
- **🔧 修正来源**：手动修正命令来源分类
- **📄 查看原始行**：展开显示 env 中的原始行内容

面板顶部的 **[＋ 为 X 新增绑定]** 按钮打开新增绑定对话框，选择修饰键层 + 输入命令后生成 Apply Plan。

#### 操作按钮（V5.6）

工具栏使用统一布局，主操作按钮突出显示，次要操作收进"更多操作"下拉：

```
[📝 生成 Apply Plan]  [✅ 执行 Apply Plan]  [⚙️ 更多操作 ▼]
  📋 变更历史  📤 导出速查表  📥 导入 env  ⭐ 仅收藏
[🔄 刷新]
```

操作说明：
- **📝 生成 Apply Plan**（蓝色主按钮）— 生成 env 修改计划，预览后确认
- **✅ 执行 Apply Plan**（绿色，有 plan 时显示）— 确认执行写入
- **⚙️ 更多操作** — 收纳变更历史、导出、导入、收藏等次要操作

#### Layer 2：快捷键地图

卡片分组展示快捷键绑定。每条快捷键卡片上会显示 **来源 env 标签**（V3.0）：
- 📝 **用户 env**（绿色）— 来自当前活动用户 env，可编辑
- ⚙️ **默认 env**（蓝灰色）— 来自 Allegro 安装目录默认 env，只读参考
- 🏢 **站点/公司 env**（紫色/橙色）— 来自站点或公司配置，只读参考
- 📄 **参考 env**（灰色）— 用户手动添加的参考 env 文件

参考 env 的快捷键卡片显示 🔒 只读标识，不可直接编辑。

支持局部筛选：

| 筛选按钮 | 功能 |
|---------|------|
| **全部** | 显示当前视图/层级下所有绑定 |
| **Funckey** | 只显示 funckey 类型 |
| **Alias** | 只显示 alias 类型 |
| **冲突** | 只显示冲突项 |
| **警告** | 只显示警告项 |
| **ATM 托管** | 只显示 ATM 托管的快捷键 |
| **用户原始** | 只显示用户原始 env 中的快捷键 |

每张卡片显示：
- **按键名** + 类型徽标（F=funckey / A=alias）
- **中文命令**（粗体蓝色，优先显示）
- **原始命令**（等宽字体）
- **快捷键来源标签** + **命令来源标签**
- **所属 Skill 名** + **加载状态警告**
- 🔒 **只读锁图标**（默认/保留键不可编辑）
- ⚠️ **覆盖风险提示**（全部叠加视图中）
- ✏️ **编辑按钮**（非只读键）
- 行号

鼠标悬停卡片可查看完整 tooltip。

搜索框支持按按键名、命令或中文名搜索。

完整字段的快捷键列表，11 列：

| 列 | 说明 |
|----|------|
| 类型 | funckey / alias 徽标 |
| 按键/别名 | 粗体显示 |
| 中文命令 | 来自命令字典 |
| 原始命令 | 等宽字体 |
| 快捷键来源 | 彩色标签 |
| 命令来源 | 彩色标签 |
| 所属 Skill/文件 | + 加载状态徽标 |
| 所属方案 | Profile 名称 |
| 状态 | 正常/冲突/前缀/无命令/保留键/禁用/已接管 |
| 行号 | 在 env 文件中的行号 |
| 操作 | 编辑/接管/修正来源按钮 |

- 选中 Layer 1 物理键时表格自动筛选到该物理键的所有绑定
- 选中 Layer 2 卡片时表格对应行高亮
- 覆盖风险项在状态列中显示 ⚠️ 覆盖风险 徽标
- 行级 tooltip 包含全部字段信息

**操作按钮：**
- **编辑 ✏️**：打开编辑对话框，修改快捷键（对话框底部显示快捷键来源 + 原始行号 + 原始命令参考信息）
- **接管 📋**：将用户原始 env 中的快捷键接管到当前方案
- **修正来源 🔧**：对**所有绑定**可用（不仅限于未识别命令），点击后弹出选择器修正命令来源分类

#### 冲突检测

自动检测并展示在页面下方：

| 类型 | 级别 | 说明 |
|------|------|------|
| funckey 重复 | 🔴 错误 | 同一个 funckey 按键被绑定两次 |
| alias 重复 | 🔴 错误 | 同一个别名被定义两次 |
| alias 前缀关系 | 🟡 警告 | 如 `s` 和 `sa`，仅提示不强制 |
| 跨类型同名 | 🟡 警告 | funckey 和 alias 同名 |
| 空命令 | 🔴 错误 | funckey 或 alias 没有命令 |

#### 编辑快捷键

点击 ✏️ 按钮打开编辑对话框，修改以下字段：
- 类型（funckey / alias）
- 按键/别名
- 原始命令
- 命令来源（手动修正）
- 启用/禁用状态
- 备注

对话框底部显示**只读参考信息**：
- **快捷键来源**标签（如"用户原始 env"、"ATM 托管块"等）
- **原始行号**：该绑定在 env 文件中的行号
- **原始命令**：重构后的 raw line

编辑时**实时检测**：相同按键是否已存在、是否为系统保留键（如 Alt+F4）、是否为软件默认占用键（如 F3）、命令是否可识别、Skill 是否可能未加载。

**编辑不会直接写文件**，而是生成编辑 Apply Plan：
1. 显示**红绿差异对比**（修改前 / 修改后）
2. 显示目标文件路径和行号
3. 自动备份 env 文件
4. 删除操作采用**安全注释删除**（`# 原行`），不物理删除行
5. 用户确认后才执行写入

### 🔤 命令字典

ATM 内置了 **200+ 条 Allegro 常用命令的中文名称、分类和说明**。

快捷键管理页面中，每条命令会自动显示中文名称：
- 已识别的命令 → 显示对应中文（如 `move` → "移动"）
- 未识别的命令 → 显示原始命令 + "未识别命令"灰色提示

**用户自定义字典：**
你可以在 `pcbenv/atm_generated/user_command_dictionary.json` 中添加自定义命令翻译，格式与内置字典一致。

### 📦 Skill 管理

管理 Allegro Skill 脚本：

**三类分类：**
| 类型 | 来源 | 操作权限 |
|------|------|---------|
| 公司 Skill | CDS_SITE / SKILL_PATH | 只读查看 |
| 用户 Skill | pcbenv/skill/ | 可启用/禁用 |
| ATM Skill | atm_generated/ | 完全托管 |

**功能：**
- 在高密度列表中查看来源、加载状态、入口命令、引用、健康度和问题数
- 启用/禁用用户 Skill

### 📋 菜单管理（V5.5）

管理 Allegro 菜单，采用 **ATM 托管菜单 Overlay** 方式，不直接修改 Allegro 原始菜单文件。

#### 工作流程

```
编辑菜单草稿 → 保存到 menu_profile.json → 预览菜单 → 生成 Apply Plan → 确认执行写入 → 从 ATM 按当前环境启动 Allegro
```

> ⚠️ **重要**：生成 Apply Plan 只是写入前预览，不会立即修改 Allegro 配置。只有点击"确认执行并写入配置"后，才会生成 `generated_menu.il` 并更新 ATM bootstrap。

#### 主工作区与工具视图

| 视图 | 说明 |
|------|------|
| **菜单树** | 唯一常驻主工作区，左侧菜单树 + 右侧详情编辑面板 |
| **命令清单** | 从“工作区工具”进入，显示哪些命令尚未加入菜单 |
| **引用检查** | 从“工作区工具”进入，检查命令缺失、Skill 未加载和标签重复 |

选中菜单目录后，使用单一 **添加** 菜单选择“添加命令 / 添加子菜单 / 添加分隔线”。

#### 菜单项类型

| 类型 | 说明 | 示例 |
|------|------|------|
| 📁 **菜单** | 可包含子项的容器 | ATM Tools、辅助工具 |
| ⚡ **命令** | 执行具体操作 | 智能吸附（绑定 snp 命令） |
| ➖ **分隔线** | 分隔同级的菜单项 | ——— |

> 分隔线和命令菜单项**不能**作为顶级节点，只能添加到某个菜单下。

#### 菜单结构规则

- 顶级节点只能是 `type="menu"`
- 分隔线不能有子项
- 命令菜单项不能有子项
- 命令菜单项必须有绑定的 command
- 启用且可见的菜单最多嵌套 8 层
- 保存草稿 / 生成 Apply Plan 前会自动校验菜单树结构

中文菜单名称和命令标签会原样保存在 ATM 方案中。Allegro 17.2 的动态菜单 API 不支持 Unicode 显示标签，因此选中中文菜单项后需填写右侧“17.2 英文兼容显示名”，例如“器件对齐”填写 `Component Align`；该字段只能包含英文、数字和 ASCII 符号。ATM 在 17.2 的 IL 中使用兼容名，在 17.4 及以后仍使用中文原名。17.2 的脚本文件继续使用 GBK，以兼容启动与中文路径。只有确认当前会话已使用同一 HOME 时，才可在普通 `Command >` 中执行 `skill (load "<generated_menu.il 的完整路径>")`；直接输入 `load(...)` 会被 Allegro 当成未知命令。

#### 菜单方案跨电脑导入导出

- 在“工作区工具”中点击 **导出当前方案**，保存为 `.atmmenu` 文件。
- 把文件复制到另一台电脑后，点击 **导入菜单方案**；先核对方案名称、菜单数量、来源/目标 Allegro 版本、命令列表和兼容提示。

- 导入完成后检查目标电脑是否安装了对应 Skill，再点击“审阅并应用”生成菜单 IL。
- 也可选择旧电脑的 `menu_profile.json`，ATM 只导入其中一个活动非空方案，不会整库覆盖。

方案包不会携带本机 Skill 绝对路径或 `.il` 文件；全部方案 ID、菜单项 ID 和父子路径会在目标电脑重新生成。同名方案自动追加“（导入）”。详细说明见 `docs/user/features/menu-profile-transfer.md`。

**操作流程：**

1. 在快捷键管理页面顶部工具栏点击 **📥 导入 env** 按钮
2. 弹出文件选择对话框，选择要导入的 `.env` 文件
3. 系统自动识别文件角色，显示导入预览
4. 选择导入模式，处理冲突后执行导入

**导入预览：**

预览弹窗显示以下信息：
- **文件信息**：文件路径、文件大小、最后修改时间
- **解析统计**：funckey 数量、alias 数量、无命令行数量
- **角色识别**：系统自动判断该 env 文件的角色（用户 env / 安装默认 / 站点 / 未知）
- **冲突检测**：与当前用户 env 和 Profile 方案的冲突列表

**四种导入模式：**

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **导入为新方案** | 将导入的快捷键创建为一个新的 Profile 方案 | 从其他电脑迁移配置 |
| **合并到已有方案** | 将导入的快捷键合并到当前选中的 Profile 方案 | 补充已有方案的内容 |
| **作为参考 env** | 将导入的 env 添加为只读参考 env | 参考其他环境的快捷键配置 |
| **高级合并到用户 env** | 将部分快捷键直接合并到当前用户 env（需 Apply Plan） | 精确控制每条绑定的合并 |

**默认识别规则：**

| 检测条件 | 自动选择模式 |
|---------|-------------|
| 导入文件来自用户 HOME/pcbenv 目录 | 导入为新方案 |
| 导入文件来自 Allegro 安装目录（CDSROOT） | 作为参考 env |
| 导入文件来自 CDS_SITE 站点目录 | 作为参考 env |
| 导入文件来自公司配置目录 | 作为参考 env |
| 无法识别来源 | 需手动选择模式（unknown） |

**冲突处理：**

导入时检测到冲突，冲突处理表支持：
- **批量操作**：一键选择全部覆盖 / 全部跳过 / 仅覆盖新键
- **逐条选择**：对每条冲突独立选择「保留原绑定」或「覆盖为新绑定」
- 冲突项显示：冲突键名、原命令、新命令、冲突类型、级别
- 覆盖操作会生成 Apply Plan，用户确认后才执行

**安全规则：**
- 导入不会直接修改用户 env 文件
- 所有修改通过 Apply Plan 流程（预览 → 确认 → 备份 → 执行）
- 导入为参考 env 模式不产生任何修改
- 高级合并模式必须先预览 Apply Plan 才能执行

## 备份与恢复

### 自动备份

每次修改配置前，ATM 会自动备份到：
```
pcbenv/atm_generated/backup/YYYY-MM-DD_HHmmss/
  ├── env                    # 备份前的 env 文件
  ├── allegro.ilinit         # 备份前的 ilinit 文件
  └── manifest.json          # 回滚清单（含 SHA256）
```

### 手动恢复

如果修改出了问题，可以从备份目录复制文件恢复：
1. 打开 `pcbenv/atm_generated/backup/`
2. 找到对应时间戳的备份文件夹
3. 将备份文件复制回 `pcbenv/`

### 设置备份与迁移（V5.7）

用于「换电脑 / 换板子」时一键带走全部软件设置，无需重新配置：

**创建备份**
1. 打开左侧「备份与恢复」页面（系统分组）
2. 点击「创建备份」，选择保存位置（默认文件名 aatm-backup-YYYY-MM-DD.atmbak）
3. 备份内容包含：
   - 板子配置：快捷键方案、Skill 方案、菜单方案、快捷键收藏、命令来源修正、Skill 元数据、已应用方案状态、多 env 来源设置
   - 应用级配置：配色方案、主窗口大小 / 位置 / 最大化状态（跨板子全局资源）
   - 界面偏好：冲突忽略列表等 localStorage 中的 UI 设置

**恢复备份**
1. 在新电脑 / 新板子上打开「备份与恢复」页面
2. 点击「选择备份文件」，选中 .atmbak 文件
3. 预览备份内容（创建时间、来源电脑、各分区条目）
4. 勾选要恢复的分区（默认全选）：
   - 板子配置：恢复到当前激活的 pcbenv
   - 应用级配置：配色方案、窗口大小 / 位置 / 最大化状态；环境注册表与更新源配置默认不恢复（新电脑路径通常不同，建议重新扫描）
   - 界面偏好：恢复后自动写回
5. 恢复窗口状态后，当前窗口会立即调整布局（含最大化状态），无需重启
6. 点击「恢复选中设置」并确认；恢复前会自动备份现有配置到 atm_generated/backups/pre-restore-<时间戳>/，如需回退可手动查看

**注意事项**
- 恢复只覆盖备份中存在的配置，不会删除本机已有的其他快捷键方案
- 恢复后建议在快捷键 / Skill / 菜单页面重新扫描，必要时重新生成并应用方案
- 备份文件为 JSON 格式，可用任意文本编辑器查看内容
## 术语说明

| 术语 | 说明 |
|------|------|
| pcbenv | Allegro 用户配置目录，通常包含 env 和 allegro.ilinit |
| env | Allegro 环境配置文件，存放 set/funckey/alias 等 |
| allegro.ilinit | Allegro 初始化脚本，启动时自动加载 |
| funckey | 即时触发快捷键（如 funckey F8 command）|
| alias | 命令别名（如 alias s save）|
| 修饰键层 | Ctrl/Shift/Alt 层级筛选，查看不同修饰组合的快捷键 |
| 普通层 | 无修饰键的快捷键，如 `c`、`1`、`F1` |
| primaryKey | 归一化后的主键名，不含修饰符前缀 |
| displayKey | 显示用键名，如 `Ctrl+C`、`Shift+F1` |
| 命令字典 | command_dictionary.json，存储 200+ Allegro 命令的中文名 |
| 命令来源 | 命令的来源分类：内置 / 本地 Skill / 公司 Skill / ATM 托管 / 未知 |
| 快捷键来源 | 快捷键绑定的物理来源：用户 env / ATM 托管 / Profile / 默认 / 保留 |
| ATM 托管块 | env 文件中由 ATM 管理的快捷键区域 |
| bootstrap | ATM 插入到 ilinit 的加载入口 |
| atm_generated | ATM 自动生成的目录，存放托管文件 |

## 常见问题

**Q: 启动后页面空白？**
A: 确认 Vite 开发服务器正在运行。访问 http://localhost:5173/ 测试。如果是 `chrome-error://` 地址，说明环境变量没设置对。

**Q: 提示 "process is not defined"？**
A: 重启 Electron，确保设置了 `$env:VITE_DEV_SERVER_URL="http://localhost:5173/"`。

**Q: 如何手动选择 pcbenv？**
A: 在"环境检测"页面点击"手动选择 pcbenv 目录"按钮。

**Q: 修改后如何生效？**
A: 大部分修改需要重启 Allegro。部分 Skill 脚本可在 Allegro 命令窗口手动 load。

**Q: 快捷键修改没有生效？**
A: 检查 env 文件中是否已有 ATM 托管块。如果块存在，只替换块内内容。如果不在托管块内，不会被修改。

**Q: "npx" 命令报错？**
A: 在 PowerShell 中需要用 
px.cmd vite` 而不是 
px vite`。或者切换到 CMD。

**Q: 键盘图层怎么切换？**
A: 键盘卡片顶部有图层工具栏，点击 **[普通]** / **[大写]** / **[Ctrl]** / **[Alt]** / **[特殊]** 按钮切换。
- 点击已激活的按钮 → 回到普通层（toggle 行为）
- 点击 **[普通]** 按钮 → 无论当前在哪层，都回到普通层
- 也可以直接点击键盘上的 **Ctrl**/**Alt**/**Shift** 键帽，功能相同

**Q: ⌨️ 我的 / 🔒 默认 / 📌 全部 有什么区别？**
A: 这是全局视图模式，位于键盘卡片头部。"我的快捷键"只显示用户自己绑定的快捷键；"默认/保留键"显示 Allegro 和系统的默认占用键（只读）；"全部叠加"同时显示两者，冲突部分用黄色标记。
