# ATM - 开发手册

## 项目概述

Allegro Toolkit Manager（ATM）是一个个人 Allegro 工作环境配置管理工具。只管理用户端可写配置层，不修改公司云端 Allegro 安装环境。

**版本：** V5.6 | **状态：** 快捷键 + Skill + 可视化菜单编辑 + UI 收口 | **日期：** 2026-06-24

## 技术栈

| 层 | 技术 | 版本 |

| 桌面框架 | Electron | ^35.1.2 |

## 架构分层

```
用户操作 → React 页面 → IPC (contextBridge) → Electron 主进程 → Core 引擎 → 文件系统
                                                      │
                                                Vitest 直接测试
```

关键约束：
- **core/** 是 pure TypeScript，仅依赖 Node.js 内置模块（fs, path, crypto）
- 所有文件操作在 Electron 主进程中执行
- React 渲染进程通过 `window.atm.*` API 与主进程通信
- core/ 可被 Vitest 直接测试，无需启动 Electron

## 进程间通信（IPC）模式

### 新增 IPC 的步骤

1. **core/ 下实现功能逻辑**（纯 TS，可测试）
2. **electron/ipc/xxx.ipc.ts** — 注册 `ipcMain.handle('xxx:action', handler)`
3. **electron/ipc/index.ts** — 注册新模块
4. **electron/preload.ts** — 在 `contextBridge.exposeInMainWorld('atm', {...})` 中添加方法
5. **React 页面** — 通过 `window.atm.xxxMethod()` 调用

### IPC 响应格式

```typescript
// 成功
{ success: true, data: ... }
// 失败
{ success: false, error: "错误信息" }
```

## 核心设计原则

1. **只管理用户端可写配置**，不碰公司云端安装环境
2. **默认只读扫描**，先诊断再修改
3. **所有修改必须生成 Apply Plan**，不允许直接写文件
4. **写入前自动备份**，失败时可回滚
5. **不全量重写 env**，只维护 ATM 托管块
6. **不反复污染 allegro.ilinit**，只插入一次 bootstrap
7. **兼容 Windows 中文路径、空格路径、非 ASCII 注释**
8. **所有异常必须可解释**：权限不足、文件占用、编码异常都要返回明确错误

## ATM 托管块

```
# ===== ATM Managed Hotkeys Start =====

# ===== ATM Managed Hotkeys End =====
```

更新时只替换块内内容，块外内容原样保留。块不存在时在文件末尾追加。

## Skill 三级分类

| 类型 | 扫描路径 | 操作权限 | UI 图标 |
|------|---------|---------|---------|
| **公司 Skill** | `CDS_SITE` 和 `SKILL_PATH` 环境变量指向的目录 | 只读查看 | 🏢 |

| **ATM Skill** | `atm_generated/` | 完全托管 | 🤖 |

## 冲突检测规则

| 场景 | 级别 | 说明 |
|------|------|------|
| funckey 完全相同按键重复 | error（红色）| 同一 env 内同键不同命令 |
| alias 完全相同别名重复 | error（红色）| 同一 env 内同名不同命令 |
| alias 前缀关系（s / sa） | warning（黄色）| 不强制报错 |
| 跨类型同名（funckey + alias） | warning（黄色）| 同名不同类 |
| 空命令 | error（红色）| 缺少命令的绑定 |
| ★ 用户 env vs 参考/默认 env 同键不同命令 | info, cross_env_override（V3.0）| 用户覆盖默认配置，非冲突 |
| ★ 覆盖默认/保留键 | warning（黄色，V4.0）| 用户绑定覆盖 Allegro 默认键 |
| ★ 命令未识别 | warning（黄色，V4.0）| 命令在字典和 Skill 注册中心均未找到 |
| ★ Skill 可能未加载 | warning（黄色，V4.0）| 命令在 Skill 中找到但未发现加载配置 |
| ★ 方案覆盖用户 env | info（蓝色，V4.0）| Profile 与用户 env 同键不同命令 |

## Apply Plan 流程

```
用户操作 → 生成 Apply Plan → 用户确认 → 自动备份 → 写入 → 验证
                                                              ↓ 失败
                                                     rollback 恢复
```

## 环境检测优先级

### 单 env 定位（locateEnvironment）

```
1. 用户手动指定 pcbenv 路径（最高优先级）
2. process.env.HOME
3. process.env.USERPROFILE
4. process.env.HOMEDRIVE + process.env.HOMEPATH
5. 常见 Cadence 路径（D:/Cadence/SPB_Data/pcbenv）
6. os.userInfo().homedir（最后回退）
```

### 多 env 来源扫描（scanEnvSources V3.0）

```
1. 手动指定路径 → 标记为 user_env（可写，主编辑）
2. HOME/USERPROFILE/HOMEDRIVE+HOMEPATH → pcbenv/env → user_env
3. SPB_Data/Cadence 常见位置 → pcbenv/env → user_env（备用）
4. CDSROOT/share/pcb/text/env → install_default_env（只读参考）
5. CDS_SITE/pcbenv/env → site_env（只读参考）
6. 设置中保存的参考路径 → reference_env（只读参考）
```

## 菜单管理模块（V5.5）

### 核心原则

1. **不直接修改 Allegro 原始菜单文件**
2. **不直接修改公司菜单**
3. 所有用户自定义菜单由 ATM 托管（ATM 托管菜单 Overlay）
4. 菜单配置保存到 `menu_profile.json`
5. `generated_menu.il` 由 `menu_profile.json` 生成
6. 所有写文件操作必须通过 Apply Plan

### 数据流

```
用户操作（添加/编辑/删除/移动菜单项）
  → React 本地状态即时更新
  → [保存草稿] → IPC menu:save-draft → 写 menu_profile.json
  → [预览] → IPC menu:generate-preview → 可视化预览 + IL 脚本
  → [生成 Apply Plan] → IPC menu:create-apply-plan → ApplyPlan
  → [确认执行] → applyPlan(JSON) → 写 menu_profile.json + generated_menu.il + 更新 bootstrap
```

### 菜单类型

| 类型 | 说明 | 约束 |
|------|------|------|
| `menu` | 容器，可含子项 | 唯一允许的顶级节点类型 |
| `command` | 执行 Allegro 命令 | 不能是顶级节点，必须有 command 字段 |
| `separator` | 分隔线 | 不能是顶级节点，不能有 children |

### 菜单树校验规则

`validateMenuTree()` 在 `src/types/menu.ts` 中实现：

| # | 规则 | 级别 |
|---|------|------|
| 1 | 顶级节点不能是 separator | error |
| 2 | 顶级节点不能是 command | error |
| 3 | separator 不能有 children | error |
| 4 | command 不能有 children | error |
| 5 | command 必须有 command 字段 | warning |
| 6 | menu label 不能为空 | error |
| 7 | command label 不能为空 | error |
| 8 | 同级 label 不建议重复 | warning |
| 9 | ID 不能重复 | error |
| 10 | parentId 必须合法 | error |
| 11 | 路径不能循环 | error |
| 12 | 启用且可见的菜单最多嵌套 8 层 | error |

有 error 时不允许生成 Apply Plan / IL。

### generated_menu.il 运行机制（V5.6）

`generateMenuIlContent()` 不替换 Allegro 原始 `.men` 文件，而是在菜单系统上叠加 ATM 托管菜单：

1. `axlTriggerSet('menu 'atmMenuOnLoad)` 监听主菜单重新加载；回调必须接收一个菜单名参数。
2. `axlUIMenuFind(nil -1)` 定位菜单栏最右侧菜单，避免依赖可能随版本变化的显示文本。
3. `axlUIMenuInsert()` 递归插入顶级菜单、子菜单、命令项和分隔线。
4. 保存 ATM 创建的顶级 `menuId`；执行 `atmLoadMenus` 时先用 `axlUIMenuDelete()` 删除旧项，再重新构建，防止重复菜单。
5. 新主菜单触发回调时旧 `menuId` 已失效，因此直接清空 ID 列表后重建。

不要在菜单触发器回调中调用 `axlUIMenuRegister()`。官方文档明确禁止这种组合；复杂菜单应在回调中使用 `axlUIMenuFind()` / `axlUIMenuInsert()`。
