# 找回不显示或乱码的菜单

当 ATM 菜单页为空，但 Allegro 里仍能看到旧菜单，通常是以下两种情况叠加：

- ATM 当前选中的 Allegro 环境与创建菜单时不是同一个 `pcbenv`。
- `menu_profile.json` 已变空，但 Allegro 仍在加载之前生成的 `generated_menu.il`。

## 恢复步骤

1. 打开“菜单”页，先查看蓝色环境提示。若菜单在其他 Allegro 环境，可点击“复制到当前 17.2/17.4”生成复制计划，也可以直接“切换到 …”查看来源方案。
2. 若出现黄色“发现可恢复的菜单方案”，点击“审阅恢复计划”。
3. 在 Apply Plan 中确认后执行。此步骤只恢复 ATM 菜单方案，不会立即改变 Allegro。
4. 检查恢复后的菜单树，点击“审阅并应用”，确认普通菜单 Apply Plan。ATM 会按当前环境版本生成脚本：17.2 使用 GBK，17.4 使用 UTF-8。
5. 关闭旧 Allegro 窗口，从 ATM 左下角点击“按此环境启动”。只有确认当前会话就是由 ATM 按同一环境启动时，才可在命令窗口执行 `atmLoadMenus` 热重载。

恢复、跨环境复制和重新应用都会先备份现有文件。跨环境复制只会在你审阅并确认 Apply Plan 后，把来源环境中的非空菜单复制为当前环境的新草稿，不会立即改变 Allegro；检查草稿后还需点击“审阅并应用”。ATM 不会根据旧 IL 反向猜测菜单源数据，也不会静默跨环境复制配置。

编辑菜单后，如果切换菜单方案、Allegro 管理目标或侧栏页面，ATM 会先保存当前草稿；保存失败或菜单结构校验不通过时会阻止切换。关闭窗口或强制刷新前仍会显示未保存提醒。菜单页内跳转到关联的 Skill/快捷键时也遵循相同保护。

如果 17.2 命令窗口出现“甯冨眬”一类路径并提示 `can't access file`，请确认侧栏当前环境为 17.2，然后在 Skill 页重新“应用此方案”。确认计划中包含 `generated_skill_loader.il`、`bootstrap.il` 和 `allegro.ilinit` 后执行并重启 17.2；原文件会先备份。不要用记事本直接覆盖启动文件。

如果 17.2 中仍出现 `²âÊÔ`、“测试3”等已经删除的菜单，请先看侧栏是否提示系统 HOME/CDSROOT 不一致。这个现象通常表示 17.2 执行文件继承了 17.4 的 HOME，正在加载 17.4 目录里的旧 `generated_menu.il`；反复清理 17.2 的菜单草稿不会删除它。关闭旧窗口并从 ATM“按此环境启动”后，再确认新菜单 Apply Plan 已执行。

若重新应用后中文仍异常，请保留新截图并记录 Allegro 完整版本号及 Command 窗口内容。

## `SPMHOD-29` 板文件版本提示

这个提示与 Skill 路径乱码是两个独立问题。它表示当前打开的 `.brd` 副本由更高版本保存，17.2 无法直接读取。请在 17.4 中打开该文件，选择 **File → Export → Downrev Design**，另存为新的 17.2 副本，再用 17.2 打开；不要覆盖唯一的 17.4 原文件，并检查导出生成的 `downrev.log`。
