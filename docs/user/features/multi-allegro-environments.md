# 多 Allegro 版本环境

## 适用场景

当电脑同时安装 Allegro 17.2、17.4、23.1 等多个版本时，ATM 的下拉框对每个版本只显示一个选项。之后快捷键、Skill、菜单的扫描和写入都会使用该版本当前选定的 `pcbenv`。

## 如何使用

1. 打开“环境”页面并执行自动检测。
2. 在环境页或左侧栏底部的“Allegro 环境”中选择要管理的版本。
3. 确认显示的安装版本、`pcbenv`、`env` 和 `allegro.ilinit` 路径。
4. 再进入快捷键、Skill 或菜单页面操作。

手动选择 `pcbenv` 会注册一个环境并将它设为当前环境。

若同一版本同时发现安装目录配置和 Windows 用户配置，ATM 会保留当前已经选中的目标；尚未选择时优先使用该版本安装目录旁的 `SPB_Data\pcbenv`。因此侧栏只会出现一个 `Allegro 17.2` 和一个 `Allegro 17.4`。可到环境页核对实际使用的完整 `pcbenv` 路径。

## 共享 pcbenv

多个 Allegro 版本可能使用同一个 `pcbenv`。ATM 会显示共享警告。此时对快捷键、Skill Loader 或菜单的修改会同时影响所有共享该目录的版本，Apply Plan 的备份与回滚也都针对这一个目录。

## 跨版本迁移

快捷键方案会记录来源环境和来源 Allegro 版本。迁移前的兼容性检查会报告：

- 来源版本与目标版本不同
- 复杂命令、FORM、模式切换或 SKILL 调用
- 命令或备注中的绝对路径
- 目标 `pcbenv` 是否被其他版本共享

“可迁移”只表示静态检查未发现已知问题，不代表目标 Allegro 已完成运行验证。复杂命令、菜单引用和自定义 SKILL 仍需在目标版本中实机确认。

快捷键页的“工作区工具”中提供“迁移当前方案到其他 Allegro 版本”。ATM 会先展示预检结果；存在绝对路径等阻断项时不会创建目标方案。

## 运行验证

环境页提供“验证当前 Allegro 会话”。该操作通过 Vibe Bridge 只读调用官方 `axlVersion` 查询版本、补丁和程序名，不修改 PCB、Selection Set 或配置文件。只有 Bridge 返回的版本与所选环境一致时，ATM 才记录 `runtime_pass`；未启动 Bridge、超时或版本不一致会保持“未验证/警告”。

## 在 ATM 中切换所选版本

侧栏中的版本选择只切换 ATM 当前管理的配置目录，不会自动打开 Allegro，也不会修改已经运行的 Allegro 进程。

切换步骤：

1. 在侧栏下拉框选择目标版本，例如 `Allegro 17.2`。
2. 点击“切换环境”，等待 ATM 刷新页面。
3. 后续菜单、快捷键和 Skill 的读取与 Apply Plan 都会指向该版本的 `pcbenv`。

若要打开 Allegro，请使用该版本自己的启动器或独立启动脚本。旧 Allegro 窗口不会因 ATM 切换管理目标而自动更换 `HOME`。
