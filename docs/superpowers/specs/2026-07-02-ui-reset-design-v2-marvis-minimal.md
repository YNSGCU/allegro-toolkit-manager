# ATM UI 重置设计稿 V2

## 背景

第一版 UI 重置虽然已经把整体主题从深色后台切到了浅色工作台，但页面仍然存在明显的“框套框”和“管理后台卡片拼贴感”。用户给出了新的视觉锚点：参考 Marvis 这类极简桌面入口的气质，要求整个产品统一成更轻、更白、更安静的语言，同时不能失去配置工具的效率。

这次设计已经通过样稿确认，方向不再是多方案对比，而是明确收敛到单一路线。

## 已确认结论

- 整个产品统一采用同一种极简语言，而不是只改首页或快捷键页。
- 视觉风格参考 Marvis 的白色体系，而不是偏彩色的工具后台。
- 页面要减少“大圆角大方格”和“层层包裹容器”的感觉。
- 产品仍然是效率优先，不是纯展示型入口页。
- 三个核心模块仍然是：快捷键、Skill、菜单。
- 快捷键页仍然作为默认入口。

## 目标

本轮 UI 重置要达成以下目标：

1. 把“后台卡片感”改成“轻导航 + 大留白 + 单主操作区”。
2. 让页面看起来像桌面端智能工作入口，而不是表单后台。
3. 保留配置工具所需的效率，不把高频操作藏得太深。
4. 三个核心页面使用同一套视觉语法，避免每页像不同产品。

## 非目标

本轮不做以下内容：

- 不改变 core / electron / IPC 的底层逻辑。
- 不改动 Apply Plan 的业务约束。
- 不新增聊天或 AI 对话能力。
- 不把配置工具彻底改造成纯首页式产品。

## 视觉方向

### 气质

整体气质以 Marvis 参考图为准，特征如下：

- 大面积白底与极浅灰分隔。
- 主要依靠留白、字号和排版层级组织内容。
- 色彩极度克制，强调色只点到为止。
- 页面中心永远只有一个主焦点。
- 导航安静，内容区松弛，不用密集块状结构制造“专业感”。

### 配色

建议使用如下白色体系：

- 页面主底：`#ffffff`
- 次级浅底：`#faf8f5`
- 分隔线：`#ece9e5`
- 主文字：`#171717`
- 次文字：`#8c867f`
- 导航文字：`#5f5b56`
- 低饱和强调色：`#0f8f84`

### 形态原则

- 去掉大面积“外层大圆角容器包住内层若干卡片”的写法。
- 圆角保留，但只用于输入面、轻卡片和局部按钮。
- 每个页面只保留少量必要的结构轮廓。
- 能用细分隔线解决的，不用再加块状盒子。

## 信息架构

### 全局结构

整个产品统一采用：

1. 左侧轻导航
2. 中央主标题区
3. 一个主输入面或主画布
4. 少量行内状态信息
5. 轻卡片式次级入口

这套结构是“入口工具化”，不是“后台模块化”。

### 导航层级

左侧只承担稳定导航，不承担大量状态展示。

分组如下：

- 核心：快捷键、Skill、菜单
- 辅助：概览、环境

导航保持轻量，不出现大段说明，不用多层边框包裹。

## 关键页面设计

### 快捷键页

快捷键页不是传统的“统计卡 + 工具条 + 明细区”。

它应该更像一个智能工作入口：

- 顶部是页面身份与当前状态说明。
- 中间是一个单一主输入面或主工作面。
- 下方是几个高价值操作入口。
- 统计数据不再先声夺人，而是退回到行内或轻卡片中。

它仍然要支持：

- 进入键盘总览
- 查看冲突
- 切换方案
- 导入导出
- 应用方案

但这些操作不应该把页面切碎。

### Skill 页

Skill 页延续同一语言，但把“输入面”替换成“主能力入口”：

- 顶部是 Skill 页身份与一句话说明。
- 主面板承载当前方案、启停状态、加载概况。
- 下方再给出“扫描 Skill”“查看引用”“命令注册中心”等轻入口。

Skill 页的重点不是展示大量表格，而是先让用户知道“当前能力状态如何，下一步该去哪”。

### 菜单页

菜单页也按同样语法处理：

- 顶部是菜单工作台身份。
- 主面板承载当前草稿状态与主操作。
- 下方轻入口进入菜单树、命令视图、引用检查、生成 Apply Plan。

菜单页不再像传统编辑器后台，而像一个进入菜单配置流程的简洁中枢。

## 组件级原则

### 保留的组件能力

以下能力继续保留，但改外观与层级：

- `Layout`
- `ProfileBar`
- `GlobalStatusBar`
- `MoreActionsMenu`
- 三个核心页的头部结构

### 需要弱化的内容

- 过多的状态胶囊并列
- 大片统计卡首屏铺开
- 多层外框与内框叠套
- 密集的后台式工具条

### 允许保留的块状元素

以下元素可以保留轻圆角：

- 主输入面
- 轻卡片入口
- 局部按钮
- 次级操作面

但这些块状元素必须是辅助，而不是整页的主结构。

## 交互原则

- 主操作始终只有一个最醒目的动作。
- 次级操作可以存在，但要弱化成轻按钮或行内入口。
- 状态信息优先回收到行内，不再优先做独立统计卡。
- 页面第一屏先给用户“我现在能做什么”，再给“我这里有多少数据”。

## 测试与验证

实现阶段仍然通过以下方式验证：

- 新增最小导航与默认入口测试。
- 运行前端 TypeScript 检查。
- 运行 Electron TypeScript 检查。
- 运行 Vitest 全量测试。
- 运行前端构建。
- 手动打开 Electron 做视觉验收。

## 风险与取舍

- 极简风格容易把工具页做空，因此必须坚持“效率优先”，不能一味删信息。
- 三个页面业务复杂度高，实现时应先改结构和样式，再逐步收口细节。
- 当前 `src/App.css` 体量较大，实现时应优先覆写高价值公共结构，不建议一次性推倒重写。

## 实施建议

实现建议按两步走：

1. 全局结构与白色视觉语言统一。
2. 三个核心页按同一模板重写首屏与二级入口结构。

完成这两步后，再进入深层组件和弹窗系统的统一。
