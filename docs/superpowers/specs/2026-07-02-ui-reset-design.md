# ATM UI 重置设计稿

## 背景

Allegro Toolkit Manager 现有功能已经比较完整，但界面仍停留在“功能堆叠”阶段。用户已经确认本次要做的是一次彻底的 UI 重置，目标不是局部修补，而是把它重新塑造成一个更像“个人桌面配置中控台”的工具。

本次设计已经经过口头确认，核心前提如下：

- 产品定位偏向轻量桌面助手，而不是重内容协作平台。
- 允许重做信息架构和视觉外壳，不要求兼容旧的页面节奏。
- 三个核心模块是最高优先级：快捷键、Skill、菜单。
- 优先级排序为：快捷键 > Skill > 菜单。
- 视觉参考只借鉴“气质”，不照抄结构。

## 目标

本次 UI 重置第一阶段的目标是：

1. 建立新的全局视觉系统。
2. 把应用默认心智入口切到“快捷键”。
3. 重做应用骨架、侧边导航、页面英雄区和顶层操作区。
4. 统一快捷键 / Skill / 菜单三页的页面节奏。
5. 在不重写核心业务逻辑的前提下，让现有页面立即呈现出新产品感。

## 非目标

本阶段不做以下内容：

- 不重写 core / electron / IPC 逻辑。
- 不整体拆分 HotkeyPage、SkillPage、MenuPage 的大文件。
- 不重做所有弹窗与每个深层子组件。
- 不新增“变更”“诊断”独立路由，只在导航层级和界面语义上强化核心模块。

## 视觉方向

### 整体气质

采用“轻量桌面助手”方向，强调：

- 浅色、安静、留白充分。
- 大圆角容器与轻阴影。
- 黑灰为正文主色，青绿色作为主强调色。
- 不是互联网内容产品，而是偏专业、偏工具型、偏个人工作台。

### 视觉参考提炼

从用户提供截图中提炼出以下可迁移元素：

- 大面积浅色背景与柔和边界。
- 左侧稳定导航，右侧大工作区。
- 主容器具有明显的包裹感，而不是满屏平铺。
- 一级按钮克制，强调“少而准”。
- 卡片化展示，而非密表格直接顶满页面。

### 设计令牌

第一阶段建议使用：

- 背景：暖白偏灰 `#f5f3ee` / `#fbfaf7`
- 面板：纯白到米白 `#ffffff` / `#fcfbf8`
- 主文本：深灰 `#171717`
- 次文本：中灰 `#6b6b6b`
- 主强调：青绿色 `#0d9488`
- 次强调：浅青色 `#d8f3ee`
- 边框：低对比暖灰 `#e8e1d8`

## 信息架构

### 导航层级

导航不再强调“系统功能目录”，而是强调“工作入口”：

- 主入口：快捷键、Skill、菜单
- 次入口：概览、环境

默认落点改为快捷键页，体现产品核心。

### 页面结构

三大核心页面统一为四层：

1. 英雄区：页面名、定位说明、关键指标、主动作。
2. 方案区：ProfileBar。
3. 状态区：GlobalStatusBar。
4. 工作区：原有业务组件，按新卡片与区块节奏重新包裹。

## 关键页面设计

### 快捷键页

快捷键页是新的首页，强调“当前方案”“冲突情况”“立即编辑”。

页面第一屏要让用户马上看到：

- 当前生效方案
- 快捷键总量
- 冲突数
- 是否存在待应用变更

原有三层结构继续保留，但外壳重做成：

- 上方总览指标卡
- 中段键盘与地图分区
- 下方明细表与冲突区

### Skill 页

Skill 页重心从“扫描结果堆栈”改为“能力编排台”。

第一屏优先展示：

- Skill 总量
- 用户 Skill 数
- 公司 Skill 数
- 引用问题状态

列表、命令注册中心、引用检查继续保留三 Tab，但整体视觉换成更轻的切页结构。

### 菜单页

菜单页重心从“编辑器”改为“菜单工作台”。

第一屏要先交代：

- 当前草稿状态
- 配置文件生成状态
- `generated_menu.il` 状态
- bootstrap 状态

树、命令视图、引用检查仍然保留，但整体变成双栏工作区，而不是强烈的系统管理后台感。

## 组件策略

### 需要重做外观的共享组件

- `Layout.tsx`
- `ProfileBar.tsx`
- `GlobalStatusBar.tsx`
- `MoreActionsMenu.tsx`

这些共享组件承担第一阶段 60% 以上的视觉变化，应优先处理。

### 尽量不动的部分

- 核心数据加载逻辑
- Apply Plan 流程
- 大部分弹窗行为
- 子组件内部复杂交互

## 交互规则

- 不再使用 emoji 作为主 UI 图标。
- hover 只做颜色、阴影、边框变化，避免布局抖动。
- 所有主操作最多保留 1 到 2 个，其他收纳到“更多操作”。
- 所有核心操作区保持同样的按钮层级。

## 响应式要求

- 桌面宽屏保持“左导航 + 右工作区”。
- 1024px 以下允许导航收窄、卡片单列。
- 不能出现横向滚动作为默认体验。

## 测试与验证

第一阶段以以下方式验证：

- 为新的导航与工作区配置新增最小可执行测试。
- 运行前端 TypeScript 检查。
- 运行 Electron TypeScript 检查。
- 运行现有 Vitest 测试集。
- 运行前端生产构建，确认样式与组件可编译。

## 实施切分

第一阶段只做“骨架换代”：

1. 全局设计令牌与浅色主题切换。
2. 新版 Layout 和导航。
3. 核心页英雄区和统一页面骨架。
4. 共享条组件外观刷新。

第二阶段再考虑：

- 深层列表与树组件精修
- 弹窗系统统一
- 图标系统补齐
- Dashboard / Environment 的进一步重构

## 风险与取舍

- 因为 `src/App.css` 体量很大，第一阶段以“覆写和替换高价值公共样式”为主，不做整文件重写。
- 由于三大页面逻辑过重，第一阶段优先改“壳”和“节奏”，不在本轮拆逻辑文件。
- 仓库当前不是 Git 仓库，因此本设计稿无法按技能要求提交 commit，只能落盘保存。
